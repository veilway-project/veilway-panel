## این مخزن چیست

Veilway یک پلتفرم VPN متن‌باز برای کسانی است که پشت شبکه‌های سانسورشده هستند: یک هستهٔ Rust، یک پنل وب و برنامه‌های رسمی. پنل، بخش مدیریت یک گره است. این بخش یک سرور Rust با SQLite است و یک برنامهٔ React که در همان فایل اجرایی ساخته می‌شود. پنل روی میزبان گره اجرا می‌شود و کاربران و تنظیمات را از راه API کنترل گره، روی سوکت unix آن، تغییر می‌دهد.

- کاربران و دستگاه‌ها: سهمیه برای هر دوره، تاریخ انقضا، گروه‌ها، فعال و غیرفعال کردن، کلید دستگاه، بازنشانی مصرف، و لینک‌ها و کدهای QR اشتراک.
- اشتراک‌ها و کلیدهای دروازه: درخواست‌ها و پاسخ‌ها سرتاسری و با کلید دروازهٔ پنل رمز می‌شوند، پس آینه‌های رله چیزی از محتوای آن‌ها نمی‌بینند. لینک‌ها کلید دروازه را دارند و صفحهٔ چرخش، سرقت و گم شدن کلید در خود پنل است. نقطه‌های پایانی نام‌دار در `sub_path/<name>` در دسترس‌اند، می‌توان آن‌ها را برای هر کاربر و هر گروه تعیین کرد و جابه‌جایی بینشان امضا می‌شود. یک نقطهٔ پایانی می‌تواند `http://` ساده باشد و پنل در این حالت هشدار می‌دهد.
- ورودی‌ها، خروجی‌ها و مسیریابی: ورودی‌های بومی و افزونهٔ اختیاری Xray، یک خروجی پیش‌فرض با خروجی‌هایی برای هر کاربر، و قاعده‌های مسیریابی که با کشیدن و رها کردن مرتب می‌شوند. یک ویرایشگر JSON خام هر تغییر را با طرح تنظیمات می‌سنجد.
- پیوندهای گره و آینه‌ها: راه‌اندازی راهنمایی‌شده برای گرهٔ ورودی و تونل معکوس، رله‌ها، و آینه‌های رله و ایستا.
- ترافیک، DNS، گزارش‌ها و اعلان‌ها: ترافیک زنده و گذشته برای هر کاربر، هر ورودی، هر خروجی و هر مسیر بیرونی، تنظیمات DNS، گزارش‌ها، و اعلان‌ها برای همهٔ دستگاه‌ها.
- مدیران و دسترسی: ورود با گذرواژه و کد TOTP، نشست‌ها، محدودیت تعداد درخواست، توکن‌های API و گزارش ممیزی. API مدیریتی با `server/openapi.json` توصیف می‌شود.
- عملیات: پشتیبان‌گیری و بازیابی، دکمهٔ به‌روزرسانی برای نصب‌هایی که با اسکریپت نصب انجام شده‌اند، لینک به صفحه‌های شرایط و حریم خصوصی خودتان، حالت نمایشی با ورود دومرحله‌ای خاموش (`"two_step": "off"` فقط در `panel.json`) که یک هشدار ثبت می‌کند، و انگلیسی و فارسی در تم روشن و تیره.

## برای چه کسانی است

برای اپراتورهایی که یک گرهٔ Veilway را اجرا می‌کنند و می‌خواهند کاربرانش را از مرورگر یا با اسکریپت مدیریت کنند. وب‌سرور شما جلوی پنل می‌ماند. TLS را خودش تمام می‌کند، مسیر مدیریت و مسیر اشتراک را به پنل می‌فرستد و بقیهٔ مسیرها را با خطای 404 خودش جواب می‌دهد. پنل فقط روی loopback گوش می‌دهد و کوکی‌هایش امن (secure) هستند.

## وضعیت

> **آلفا.** سرور و برنامهٔ وب ساخته شده‌اند و در آزمون آلفا با یک گرهٔ واقعی اجرا می‌شوند. این مخزن هنوز نسخهٔ منتشرشده‌ای ندارد و پنل بررسی امنیتی بیرونی نداشته است.

## شروع سریع

این مخزن هنوز نسخهٔ منتشرشده‌ای ندارد، پس اول از روی سورس بسازید (بخش زیر). بعد، داخل `server/`:

۱. فایل `panel.json` را بنویسید. همهٔ کلیدها اختیاری هستند، ولی پنل شروع نمی‌کند مگر `trusted_proxies` وب‌سرور شما را فهرست کرده باشد (یا وقتی پروکسی‌ای جلوی پنل نیست، `direct` برابر `true` باشد). برای `prefix` یک مسیر تصادفی و بلند بگذارید، چون مسیر مدیریت است. برای `not_found` وضعیت، سرآیندها و بدنهٔ خطای 404 وب‌سرور خودتان را همان‌طور که هست کپی کنید.
۲. پنل را اجرا کنید:

```
cargo run -- run --config panel.json
```

در اولین اجرا، یک توکن راه‌اندازی یک‌بارمصرف در کنسول چاپ می‌شود. آن را خصوصی نگه دارید.

۳. اولین حساب مدیر را بسازید: توکن را همراه با نام کاربری، گذرواژه و `"accepted_terms": true` به `{prefix}/api/setup` بفرستید. پنل در راه‌اندازی پذیرفتن شرایط Veilway را لازم می‌داند. پاسخ یک راز TOTP دارد. آن را به یک برنامهٔ احراز هویت اضافه کنید و با کد آن وارد شوید.
۴. پیش از افزودن کاربر، نشانی نقطهٔ پایانی، استخر نشانی و پروفایل‌ها را در پنل تنظیم کنید.
۵. برای ورود، `{prefix}` را در مرورگر باز کنید.

## ساخت از روی سورس

مخزن هستهٔ Veilway را کنار این مخزن کلون کنید. سرور `veilway-proto` را از `../../veilway/crates` می‌خواند، پس پوشه‌ها باید کنار هم باشند:

```
git clone https://github.com/veilway-project/veilway
git clone https://github.com/veilway-project/veilway-panel
cd veilway-panel
```

آزمون‌ها را در Docker اجرا کنید:

```
docker run --rm --cpus 3 --memory 3g -v "$PWD":/w/veilway-panel -v "$PWD/../veilway":/w/veilway -v veilway-cargo:/usr/local/cargo/registry -v veilway-target-usage:/t -w /w/veilway-panel/server -e CARGO_TARGET_DIR=/t/target/panel rust:1 sh -c "cargo test"
```

بعد از تغییر یک مسیر یا یک نوع، `server/openapi.json` را با همان دستور بسازید، با این تفاوت که به جای `cargo test` از `sh -c "cargo run -- openapi > openapi.json"` استفاده کنید. اگر این فایل قدیمی باشد، یک آزمون شکست می‌خورد.

## اجرا با Docker

اسکریپت نصب راه پیشنهادی است و Docker یک گزینه است. تصویرهای linux/amd64 و linux/arm64 با هر برچسب `v*` در `ghcr.io/veilway-project/veilway-panel` منتشر می‌شوند. تصویر با کاربر غیر ریشه اجرا می‌شود و تنظیمات و داده‌هایش در volumeها هستند. پنل فقط روی `127.0.0.1` گوش می‌دهد، پس یک وب‌سرور با TLS جلوی آن لازم است و به سوکت کنترل گره هم نیاز دارد.

کانتینر را با سیاست راه‌اندازی دوباره اجرا کنید: `--restart unless-stopped` یا در compose مقدار `restart: unless-stopped`. بعد از بازیابی از پشتیبان، پنل خودش با کد خروج 75 می‌ایستد تا سیاست راه‌اندازی دوباره آن را روی فایل‌های بازیابی‌شده بالا بیاورد. بدون این سیاست متوقف می‌ماند. دکمهٔ به‌روزرسانی داخل کانتینر کار نمی‌کند: به جایش تصویر تازه را pull کنید.

[deploy/compose](https://github.com/veilway-project/veilway/tree/main/deploy/compose) در مخزن هسته، گره و پنل را با هم اجرا می‌کند و مراحل تنظیمات، volume سوکت و وب‌سرور را دارد.

## API

API مدیریتی زیر `{prefix}/api` قرار دارد. جدول مسیرها در `server/src/routes.rs` هم روتر را می‌سازد و هم `openapi.json` را، پس این فایل همیشه با کدِ در حال اجرا یکی است.

توکن‌های API به یک اسکریپت اجازه می‌دهند API مدیریتی را صدا بزند. توکن هرگز به مسیرهایی که نشست کامل مدیر یا احراز هویت دوباره لازم دارند نمی‌رسد.

## نکته‌های امنیتی

- ورود مدیر، علاوه بر گذرواژه، کد TOTP هم می‌خواهد. گذرواژه‌ها با Argon2id هش می‌شوند.
- پنل میزبان و مبدأ درخواست‌های مدیریتی را بررسی می‌کند. `allowed_hosts` نام میزبان‌هایی را که می‌پذیرد فهرست می‌کند.
- `trusted_proxies` پروکسی‌هایی را فهرست می‌کند که پنل نشانی ارسال‌شدهٔ آن‌ها را باور می‌کند. آن را فقط روی وب‌سرور خودتان نگه دارید.
- سه فایل، جدا از هم و فقط با دسترسی مالک (حالت 600): پایگاه داده هیچ کلیدی ندارد، `panel.keys` کلیدهای توکن و راز را دارد، و `signing.keys` کلیدهای امضای اشتراک را. `panel.keys` را جداگانه پشتیبان بگیرید. بدون آن، نقطهٔ پایانی اشتراک مثل یک مسیر ناشناس جواب می‌دهد و هیچ رازی باز نمی‌شود.
- `gateway.keys` کلیدهای دروازه را دارد که درخواست‌های اشتراک را باز می‌کنند و پشتیبان پنل آن را شامل می‌شود. نیمهٔ خصوصی کلید بعدی یک بار در `gateway.next` نوشته می‌شود تا آن را از سرور ببرید و نگه دارید.
- پنل TLS ندارد: روی `listen` غیر از loopback شروع نمی‌کند و کوکی‌هایش امن هستند.
- نقطهٔ پایانی اشتراک شبیه صفحهٔ 404 خود وب‌سرور است. تنظیم `not_found` همان پاسخ را کپی می‌کند، پس یک غریبه نمی‌تواند نقطهٔ پایانی را از هر مسیر گم‌شدهٔ دیگری تشخیص دهد.
- گزارش ممیزی هرگز لینک، توکن یا کلید را نگه نمی‌دارد.
